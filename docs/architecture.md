# 架构与代码边界

React 渲染器通过 `window.mise` 请求主进程。`electron/preload.ts` 是唯一桥接入口，共享 API、命令结果与配置类型位于 `src/types.ts`。

## 主进程

- `main.ts` 负责窗口生命周期、来源受限的 IPC 注册及命令调度。
- `ipc.ts` 验证流式命令参数、渲染器 URL，并确保命令成功、失败和启动异常都以一个退出事件结束。
- `mise.ts` 发现可执行文件，执行参数化的 mise 子进程，解码 UTF-8 和回车进度，归一化查询结果。
- `pins.ts` 建立全局、已跟踪及手动引入的配置集合，并处理缓存失效。
- `config.ts` 校验目标路径与 TOML，限制配置文件读写范围。
- `connections.ts` 校验新鲜状态并处理版本切换、跨文件改接、停用及恢复。跨文件第二步失败时，仅在目的文件仍是本次写入内容时回退。
- `disabled.ts` 原子保存停用请求。损坏的元数据不遮蔽真实 mise 工具列表；写操作仍严格读取，避免静默覆盖无法恢复的数据。
- `envdir.ts` 统一目录默认值、持久化环境覆盖和 Windows 写入；`bootstrap.ts` 与 `installer-script.ts` 负责用户主动发起的官方安装流程。

## 渲染器

`App.tsx` 协调页面数据、配置选择、输出与全局忙碌状态；公共命令异常转换集中在操作执行器中。数据加载在页面／配置变化时取消旧结果提交，并提供失败重试。

`ToolsPane` 组合工具卡片、配置节点、SVG 连线和画布工具栏。`useToolCanvas` 管理视图、节点坐标及布局偏好；`useToolCable` 管理指针捕获、命中判定、预览及端点改接。`canvas.ts`、`toolLinks.ts` 中的几何计算不执行 mise。

`devMock.ts` 只在开发环境且没有 Electron 桥时动态载入。生产构建不包含模拟 API。TOML 使用同一个具有浏览器实现和类型定义的 `smol-toml`，渲染器不依赖 Node polyfill 或动态代码求值。

## 验证层次

单元回归覆盖解析、路径范围、目录来源、安装传输、连接事务、几何及 IPC；桌面回归覆盖缺失 mise 和失败恢复；图形回归使用受控 IPC；真实 mise 回归在隔离目录中验证实际命令和文件结果。

各套 Electron UI 回归顺序执行，避免窗口焦点干扰拖拽。CI 不写入用户配置，不安装 mise。
